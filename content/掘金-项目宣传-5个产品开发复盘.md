# 一个前端仔用Vue3+AI，3周撸了5个能上线的产品

> 从抠图到证件照，从文案生成到成语游戏，一个人一条技术栈，把"想法"变成"产品"的过程远比想象中快。

## 为什么做这件事

去年底有个很强烈的感受：前端开发者总在给别人做产品，很少给自己做产品。我们每天都在写需求、改bug、优化性能，但对"从0到1把一个东西做出来并推到用户面前"这件事，经验其实很少。

另一个原因是 AI 能力的爆发。rembg、DeepSeek 这些能力的开放，让原本需要后端团队配合才能做的事，前端一个人就能搞定。我就想试试：一个人、一套技术栈，到底能做多快？

结果是用大约3周时间，做出了5个产品，全部上线可访问。

## 产品矩阵

### 1. AI智能抠图小程序

微信小程序，用户上传一张图，AI自动抠出人像，支持换背景色和保存。核心用的是 Body Segmentation API，前端调用后端服务返回抠图结果，配额管理用本地存储按天计数，看广告可以额外获得次数。

技术亮点：整个抠图流程封装在 `useCutout` composable 里，选图→转Base64→调API→存结果→跳转结果页，一气呵成。小程序端用 `uni.request` 的 `enableChunkedTransfer` 模拟流式传输，H5端用原生 fetch + ReadableStream。

### 2. 成语答题小游戏

微信小程序，每日答题模式，有连击加分、复活机制、答题计时。题库是从开源成语数据清洗生成的，按难度分级。

技术亮点：游戏状态管理比较复杂——当前题目、答题记录、连击数、分数、复活次数、计时器，全放在 Pinia 的 `useGameStore` 里统一管理，支持持久化到本地存储，中途退出回来能恢复进度。

### 3. 证件照制作工具

Web应用（[photo.huiquicktool.cn](https://photo.huiquicktool.cn)），上传照片→AI抠图→选尺寸选背景色→美颜调节→下载。支持一寸、二寸等常见规格，还有A4排版打印功能。

技术亮点：这个项目最硬核的部分是**纯前端AI抠图**。用了 `@imgly/background-removal` 这个库，它基于 ONNX Runtime 在浏览器里跑 U2Net 模型，WASM 加载 + 模型下载大概要几秒到十几秒。为了优化体验，做了模型预加载、图片压缩（超过1024px自动缩放）、抠图结果缓存（同一张图不重复处理）。排版功能是用 Canvas 画的，自动计算行列数和裁切线。

### 4. AI文案生成助手

微信小程序，内置7个场景：朋友圈文案、小红书标题、外卖好评、工作周报、祝福语、道歉信/感谢信、个性签名。用户填几个字段，AI流式生成多条结果，支持一键复制。

技术亮点：场景配置和数据驱动设计，每个场景的表单字段、提示词模板都定义在 `scenes.ts` 里，新增场景只需加配置不改逻辑。流式输出做了双端适配——H5 用 `fetch + ReadableStream`，小程序用 `uni.request` + `onChunkReceived` 回调，用条件编译 `#ifdef` 切换。AI输出解析器也比较有意思，要处理各种格式：带【风格】标签的、带数字序号的、带emoji序号的，都做了正则匹配。

### 5. 开发者工具集合站

Web应用（[huiquicktool.cn](https://huiquicktool.cn)），集成了JSON格式化、Base64编解码、时间戳转换、正则测试、颜色转换等常用开发工具，支持暗色模式。

技术亮点：Vue3 + Vite + Vue Router 的纯 SPA，每个工具是一个 View 组件，组合式函数抽取了 `useCopy`（复制到剪贴板）和 `useTheme`（主题切换），主题状态存在 localStorage 里，跟系统偏好自动同步。

## 技术选型思考

### 为什么是 Vue3 + Vite + uni-app？

选型的核心原则是**一套代码多端运行**。5个产品里3个是小程序、2个是 Web，如果每个平台用不同框架，维护成本直接翻倍。

uni-app 在 Vue3 + Vite 模式下的开发体验已经很成熟了，组合式 API 支持、TypeScript 支持、条件编译都是开箱即用。相比 Taro，uni-app 的模板语法更接近原生 Vue，学习成本低；相比原生小程序开发，效率高太多。

Vite 的冷启动速度和 HMR 是刚需，5个项目来回切的时候，等 Webpack 构建是真的受不了。

### 为什么选这些 AI API？

- **抠图**：`@imgly/background-removal` 纯前端跑，不需要后端，省了服务器成本。小程序端用 Body Segmentation 云端 API，按次计费，配合配额系统控制成本。
- **文案生成**：DeepSeek API，性价比高，`deepseek-chat` 模型的中文文案能力够用，流式输出体验好。

## 踩过的坑

### WASM 加载和模型体积

证件照工具用的 `@imgly/background-removal`，首次加载要下载 ~40MB 的 ONNX 模型文件。国内网络环境下，这个加载时间很容易超时。

解决方案：加了模型预加载机制——页面打开后立即 `initModel()`，不阻塞用户操作；模型加载进度实时显示；图片上传前自动压缩到 1024px 以内减少处理时间；同一张图的抠图结果做缓存。

### 国内 Docker 镜像拉取

后端服务部署在 1Panel 管理的 Docker 环境里，国内拉 Docker Hub 镜像经常超时。最后配了国内镜像加速器（registry-mirrors），在 `/etc/docker/daemon.json` 里配置：

```json
{
  "registry-mirrors": [
    "https://mirror.ccs.tencentyun.com"
  ]
}
```

腾讯云的镜像加速器在国内速度还可以，基本解决了拉取问题。

### 微信小程序审核

这个坑最花时间。审核被拒的原因五花八门：

- AI文案生成工具被判定为"AI生成内容类"，需要补充用户协议和免责声明
- 抠图小程序的"看广告获得次数"设计，起初是弹窗强制看广告才能继续，被审核打回，改成了用户主动选择看广告
- 个人主体小程序类目限制多，很多功能类目不支持个人开发者

经验就是：提前看审核规范，个人开发者能做的类目有限，别做完了才发现类目不对；广告不要做成强制的；AI相关功能一定要有免责声明。

### 小程序流式输出的兼容性

DeepSeek 的流式输出在小程序端和 H5 端实现方式完全不同。小程序的 `uni.request` 支持 `enableChunkedTransfer`，但回调的 `onChunkReceived` 返回的是 ArrayBuffer，需要手动转字符串、手动做 SSE 解析、手动处理不完整的行（buffer 机制）。H5 端直接用 fetch + ReadableStream 就行。

最后用条件编译 `#ifdef MP-WEIXIN` 和 `#ifdef H5` 分别实现，对外暴露统一的接口。

## 总结和感悟

几个很实际的感受：

1. **AI把独立开发的门槛拉低了**。抠图、文案生成这些功能，放到两年前要么得自己训练模型，要么得找后端配合，现在调个API就行。证件照工具甚至能在浏览器里纯前端跑AI模型。

2. **技术选型比技术实现更重要**。选 Vue3 + uni-app 让5个项目共享一套技术栈和大量工具函数（配额管理、广告加载、存储封装），换框架的成本几乎为零。

3. **审核和运维才是最耗时间的**。开发3周，审核和改版又花了2周。Docker镜像拉取、SSL证书、域名备案这些"非技术"工作，占了总时间的30%以上。

4. **产品矩阵 > 单品**。5个产品互相引流的效果，比单独推一个产品好得多。用户用完抠图工具，顺手就看到了文案生成工具。

如果你也是前端开发者，想试试独立做产品，我的建议是：**先别想太多，用你熟悉的技术栈把第一个东西做出来上线**。过程中的坑才是真正的经验。
